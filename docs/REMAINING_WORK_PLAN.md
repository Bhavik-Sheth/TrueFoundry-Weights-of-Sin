## Product milestone

A reviewer opens a request, follows its tool calls to individual hunks, inspects checks against the exact revision, and records a decision. The same review opens from an imported agent trace, survives a restart, and can coexist with a second run. If that second run edits the same file, the second apply must revalidate the file version. This scenario drives implementation across all eight areas.

## Implementation contracts

### 1. Registration reliability

Extract one reconcile function for the CLI and wizard. Read the connector and agents by stable identity, create missing resources, update drift on Contexo-owned fields, then read back the effective configuration. A 409 triggers lookup and comparison. Treat 401/403, unknown model 422, incompatible server, and unreachable connector as distinct results. Keep partial successes so rerunning repairs the missing resource. Redacted secrets cannot establish equality: rotate only on explicit credential change. Print a summary with secrets omitted. Keep resource registration and connectivity as separate outcomes. Replace the implicit latest-server dependency with an explicit supported version or a capability check for a user-managed server.

### 2. Storage, identity and replay

Keep TypeScript for the extension host, SDK, webview and adapters. Use a transaction-capable local store for event metadata and projections and content-addressed files for diffs and large outputs. Decide the SQLite driver against the actual VS Code Electron/Node versions before introducing a native dependency. Retain JSONL as the portable interchange format. Rust is an option for a measured indexing or import bottleneck. Introducing a binary now would add a distribution target for every local and remote extension host.

A versioned event carries event ID, source event ID, run/session/turn/thread IDs where known, parent operation ID, workspace and root IDs, observed and source times, schema version, payload, and artifact references. Put requirements, proposals, hunks, approvals and checks under stable IDs. Deduplicate on source namespace and source event identity. For offline files without event IDs, use file digest and record position. Preserve unknown vendor fields separately. Missing diffs, redacted results and gaps stay visible. Store immutable source facts separately from derived UI state.

Write artifact to temporary file, verify digest, rename, then commit references and cursor in one transaction. Recover orphan blobs after a grace period. Migrate v1 by copying and validating before switching readers. Retain originals. Support bounded import sizes, path validation, credential redaction and an export preview because tool arguments and output can contain secrets or proprietary code.

Deliver three adapters first: native Contexo v1/v2, recorded ACP session updates, and OTLP JSON spans with a documented GenAI attribute mapping. Use parent span IDs to reconstruct nesting and explicit content events for tool input/output. Add producer fixtures for each supported version; describe format coverage per adapter. Render playback through a pure reducer with checkpoints for seeking. Playback never invokes a tool, writes a file, or sends an approval. ACP session loading and Langfuse's OpenTelemetry ingestion illustrate the two distinct source shapes. [ACP session setup](https://agentclientprotocol.com/protocol/v1/session-setup) · [Langfuse OpenTelemetry integration](https://langfuse.com/integrations/native/opentelemetry)

### 3. Recovery and ownership

Persist a pending proposal before opening the diff: exact base text or blob digest, patch, root URI, accepted/rejected/undecided hunks, tool call, approval ID and source cursor. Persist each decision. Persist apply intent before file writes, then record per-file completion and the final result. After restart compare current content to both base and reviewed target. Already at target means complete; still at base means eligible to finish; divergent means show a conflict. Keep the existing recover-apply behavior while migrating older checkpoints.

For a dropped stream, subscribe using the pinned SDK's exclusive afterEventId cursor and deduplicate received events. Re-read authoritative turn state and outstanding approval identity before enabling Apply. If the cursor expired, rebuild from persisted server history. If delivery of an approval timed out, first query the server for that exact call. Keep ambiguous cases pending and disable duplicate execution. A fallback session gets a new identity and cannot inherit write authority. Show offline replay when the server is unavailable. [TrueForge session API](https://github.com/truefoundry/trueforge/blob/main/docs/api/use-agent.mdx)

Replace the singleton active run with a registry keyed by run ID. The selected tab is a view preference. Route every approval, subprocess, stop signal and late event through its originating run. Bind MCP authority to a trustworthy per-session identity or a dedicated run-scoped connector credential. A model-supplied runId is insufficient. Hold mutating concurrency behind this dependency. Acquire file locks in deterministic URI order and check versions again while holding them. Preserve separation between a remote workspace host, the user's local UI and the configured TrueForge host; loopback addresses are host-relative. Use WorkspaceFolder URIs and workspace.fs for document I/O, with explicit capabilities for native subprocesses and virtual filesystems. [VS Code remote extensions](https://code.visualstudio.com/api/advanced-topics/remote-extensions) · [Multi-root workspaces](https://code.visualstudio.com/docs/editing/workspaces/multi-root-workspaces)

### 4. Requirements, findings and code intelligence

Let users split a request into editable requirement records. Keep the original text, stable ID and revision. A user or agent can propose links to hunks. Record link source, rationale, base/target revision and reviewer decision. A passing job is evidence about its tested revision and scope. It covers a requirement only through an explicit association. Show verified, failing, stale, conflicting and unassessed evidence independently.

Normalize SARIF artifact locations, uriBaseId and line/column regions, preserving rule IDs and partial fingerprints. Match the reported revision and diff side before intersecting regions with changed lines. File-only results remain file-level. Preserve multiple locations and handle renames, deleted lines, rebases and findings outside edited hunks. Keep external evidence immutable when the user changes a disposition. [GitHub SARIF support](https://docs.github.com/en/code-security/reference/code-scanning/sarif-files/sarif-support)

Use VS Code definition, references, implementation and call-hierarchy providers on demand; track provider availability, cancellation and document version. Normalize URI/Range and LocationLink results. Index imports with language-aware parsing where available. Distinguish exact provider results from inferred text matches. Cache by root, language, document version and provider identity; invalidate dependents on edit, rename and delete. Build the before graph from the base revision and the after graph from the candidate snapshot. Providers that only understand open workspace files may require a distinct workspace host for the candidate; otherwise label the after graph unavailable. Show directly changed edges first, with bounded expansion to callers and tests. [VS Code language features](https://code.visualstudio.com/api/language-extensions/programmatic-language-features)

### 5. BYOK evidence integrations

Give each connection an ID, endpoint, credential reference, repository/root mapping, cursor and last successful sync time. Store credentials in VS Code SecretStorage and keep them out of journals, workspace settings, redirects and webviews. Fetch evidence in the extension host. Use pagination, cancellation, bounded retries and stable external IDs. Expose revoked credentials, partial results, and a refresh action. Manual review decisions live locally; sending a decision back to a service is a distinct user action.

### 6. Runtime capabilities

The pinned SDK exposes skills clients and session subscription cursors. TrueForge documents git-backed skills and advertises Code Mode. Its advertised feature set does not establish that every deployed server has an available sandbox or that a manifest field named codeMode exists.

Persist a capability snapshot per connection and distinguish configured, available, observed in a run and failed. For Skills, list allowed sources, resolve a version, display instructions/provenance for review, associate the selected version with the agent, and record actual loading when observable. For Code Mode, confirm the supported discovery and invocation path against the selected server release, display sandbox prerequisites, route execution through the runtime, preserve approval policy for side-effecting tools, and surface artifacts, timeout and cancellation. If the server lacks support, explain the missing capability. Expose subagent and compaction events in the same replay model with parent/thread relationships and retained history. ## Verification phase after implementation

1. Registration: clean install, existing identical configuration, drift, invalid model, denied permissions, partial failure, rerun and exit code.
2. Replay: round-trip a native run; import ACP and OTLP; duplicate, reorder, truncate and redact records; seek backward; confirm zero replay side effects.
3. Recovery: terminate the real editor after staging, after one decision, during apply, and after remote approval but before acknowledgement. Verify file contents, approval count and terminal state against TrueForge.
4. Evidence: two requirements share a hunk, a check refers to an older revision, a finding touches a deleted line, a reviewer overrides an inferred link, and a provider returns no SCM metadata.
5. Integrations: combine recorded contract fixtures with one authorized read-only live connection per provider. Verify token revocation, pagination and repeat sync. Use existing BuildKit artifacts while Docker is paused.
6. Workspace: run two jobs in two same-named paths, two jobs touching the same file, a remote SSH workspace, and a virtual filesystem without subprocess support. Cancel one run and confirm the other continues.
7. Runtime: use actual tool-capable primary and fallback chat models for Flask A/B/C. Capture a skill load, child thread, compaction and Code Mode invocation on a capable server. Compare resulting files, checks and approvals with the exported replay.
8. Release: record commit, SDK/server, VS Code, model and provider versions; separate fixture, packaged-host and live-provider evidence. Reopen the final review from a clean profile using only its export.

## Tracking and release decisions

Use one issue or PR per numbered change. Track owner, prerequisite, implementation commit, migration impact, remaining blocker and verification artifact. Move from planned to implementing to merged to verified only when the corresponding artifact exists. The first integration milestone is a replayable native proposal that can be reopened after restart. The second is a requirement linked to one reviewed hunk and one revision-matched external check. ## Engineering work packages

Paths in this section are relative to `extension/` unless prefixed with the repository root. A new filename or method below describes a proposed change. Start each package by reading its named current implementation. Adapt names when the branch changes while preserving the stated behavior.

### A. One registration operation for both entry points

1. In `trueforge/register.mjs`, the three catch blocks currently print warnings and execution reaches the end. This is how a real 422 produced a successful shell exit. Move SDK calls into a VS-Code-independent reconciler, for example `src/run/reconcileRegistration.ts`. Bundle a small Node CLI entry with esbuild so the script and `createAdmin` consume exactly one implementation. Keep JSON manifests and their existing camelCase parity test.
2. Validate endpoint, chosen model names and required credential references before making a change. Resolve the two models through the server list. Construct the desired connector and two agents with `buildConnectorManifest` and `buildAgentRequest`. Compare only Contexo-owned fields; preserve server-generated IDs, timestamps and unrelated operator settings.
3. Return three records containing resource name, operation, outcome, observed resource ID and a sanitized reason. A resource can be created, updated, already correct, blocked by a failed prerequisite, or failed. First establish the connector, then reconcile each agent. If only the fallback fails, leave the working primary in place and report partial success. Re-running uses the same names. A name conflict with a different owner must produce a visible conflict before overwriting.
4. On timeout following a write, read by stable identity. If desired state exists, acknowledge it. If a resource exists with conflicting configuration, show the conflict. If observation is impossible, report unknown. Set `process.exitCode = 1` for failed, blocked or unknown required resources. The wizard should show the same per-resource outcomes and keep the failed step open. Keep secrets out of error dumps, including nested SDK request objects.
5. Store the server version or capability response and SDK version in the run header. If discovery fails, store “unknown” and use only confirmed functionality. A successful agent registration does not establish model inference, MCP reachability or editor approval delivery; those have separate probes.

This uses the AWS distinction between retrying one intended operation and submitting a new operation with similar arguments. A stable intent ID plus a digest of the intended configuration permits safe reconciliation. Reusing an ID with different content is an error. [AWS Builders’ Library](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/)

### B. Store events once and rebuild the screen from them

Today `RunJournal.record` allocates sequence numbers in process memory; `flush` drains a promise queue. A restarted writer cannot safely resume the same run from that counter. In `src/run/journal.ts`, introduce a promise-returning append API. Critical operations such as displaying a pending review, acknowledging Apply or advancing a remote cursor must await the commit. Token display can still stream immediately. Batch text deltas and retain the final message plus timing detail where available. Mark history imported from v1 with its actual content limitations.

Proposed logical schema:

| Record | Identity and constraints | Why it exists |
|---|---|---|
| runs | run ID, workspace ID, runtime URL identity, session IDs, created time, schema version | Locate a run after a restart or import. |
| events | unique (run ID, sequence); unique (origin namespace, run ID, source event ID) when available; immutable payload and digest | Record a fact once, detect an apparent duplicate with different contents. |
| artifacts | content digest, byte length, media type, storage location, redaction status | Share identical patches across events and detect missing or damaged content. |
| reviews | run, proposal, base hashes, candidate hashes, decision revision, status | Restore the diff at a particular revision. |
| effects | operation ID, payload digest, intent, observed result or unknown | Reconcile applying a file or answering a remote approval after interruption. |
| subscriptions | runtime, session, turn, last durably consumed source cursor | Subscribe at the correct point without losing events. |

Allocate the next sequence inside the same serialized transaction as event insertion. Write and flush blob bytes in the destination filesystem, then rename in that filesystem, then commit references. If durability promises include power loss, verify file and directory sync behavior on supported hosts. A database transaction cannot atomically commit updates to arbitrary workspace files or TrueForge. Use the effect ledger and reconciliation for those. If storage fills, surface an actionable error, retain pending decisions, and suspend new effectful actions until durable recording works. Bound retention by bytes and age; show what runs will be affected and preserve artifacts referenced by retained runs. Never delete the old journal during migration. Mark a migration complete only after event counts, digests and repeat reads agree. [SQLite atomic commit](https://sqlite.org/atomiccommit.html)

### C. Import and playback, step by step

Add `src/replay/importers/{native,acp,otlp}.ts` and a pure reducer. Each adapter accepts a byte stream plus explicit format/version, yields canonical events and a diagnostics summary, and never receives a workspace writer, process runner or approval client. Stage an import under a new ID. Publish it only after validation; a cancelled import must leave no partially visible run. Treat external paths and Markdown links as untrusted display data. Resolve artifacts only in the selected import archive and reject traversal, absolute paths, decompression bombs and excessive nesting.

Native v1 maps its request, tool output and proposal snapshots into v2. A recorded ACP update stream can supply content, plan updates and tool-call changes; use its tool-call ID to update the same timeline item. An OTLP span adapter uses trace ID, span ID and parent ID, start/end timestamps, events and available attributes. A missing parent produces a visible orphan. External spans can overlap. Show parallel intervals and keep a deterministic presentation order; sorting by timestamp alone cannot prove causality. Handle clock skew and provider redaction. Export a versioned manifest listing each artifact and checksum. Version mismatch with an unrecognized major schema opens an import diagnostic with the original preserved. [OpenTelemetry Trace API](https://opentelemetry.io/docs/specs/otel/trace/api/)

Replace the raw-record-only command in `src/extension.ts` with an entry that also opens the replay viewer; retain raw JSONL inspection. In the webview provide previous/next, jump to proposal/check/approval, speed, pause, current event and a text alternative to the timeline. Seeking to event 500 restores the nearest projection snapshot and reduces the remaining events. Cache snapshots only as an optimization. Starting from event zero must yield the same view. Show the diff as it existed at that step even if the workspace has since moved.

### D. Restore pending decisions and reconnect the server turn

Change `ReviewEngine.beginProposal` to save the base/proposed blobs and stable hunk IDs before the first diff opens. Change `setDecision` and `acceptAll` to persist one versioned decision operation. Make CodeLens callbacks await it. Include proposal ID and expected decision revision so clicking a stale lens cannot silently change a newer proposal. Restore the virtual documents and lenses from those blobs on activation. Replace the closure-only approval resolver with a persisted address (runtime, session, turn, thread, tool call). Construct the live resolver from that address only after reconciliation.

| On restart | Local action | Server action and UI |
|---|---|---|
| Pending, same bases, server still waiting on same call | Restore exact accepted/rejected/undecided selection | Enable review; show when approval state was last refreshed. |
| Local Apply intent, file equals base | Remaining write may be resumed under lock after revalidation | Read server approval state before dispatching any answer. |
| File equals target | Mark that file observed complete; restore missing undo entry once | If approval remains pending, deliver the saved outcome once. |
| File equals neither | Pause and expose base, candidate and current text | Keep approval unresolved until the user chooses a fresh review or denial. |
| New-file candidate, zero-length file now exists | Treat path existence separately from content hash | Require a fresh comparison; a user-created empty file is distinguishable from absence. |
| Server finished or cancelled while editor was closed | Restore read-only history; clear live authority | Show authoritative terminal status and any mismatch. |
| Approval delivery unknown or server unreachable | Preserve intent and disable repeated side effects | Re-query; offer offline history and explicit reconnect. |
| Server cursor rejected or aged out | Rebuild from paginated persisted history and deduplicate | Attach using latest committed cursor after recovering the gap. |

In `RunManager.resolveApproval`, record intent before sending. In `TfClient`, add a read-only reconcile operation and a subscribe-only path for an existing turn; keep starting a new turn a separate method. In `withMerge`, retain a stable ID for partial tool calls across reconnect. Never interpret empty message placeholders as complete tool arguments. Drop the `finalizeLatest` fallback for ambiguous calls as run concurrency comes online. In `applyUndo.ts`, account for unsaved editor buffers and document versions. If formatting-on-save changes the result, record the actual saved hash and show divergence. Do not report an exact apply based solely on a successful save boolean.

### E. Requirement and finding evidence with a worked example

For Task B create separate requirements for command discovery in help, JSON output, masking, tests, and documentation. Retain the original instruction verbatim alongside these user-editable records. Give each item a UUID and increment its revision on material edits. In the Changes tab let the user choose a requirement and link specific hunks. An agent may suggest the link with a reason. A human can confirm or reject it. Record these as events; the original request and previous decision remain readable.

Example: an accepted hunk changes the masking predicate, another adds a masking assertion, and Jenkins reports success at commit X. The first hunk implements the requirement; the second exercises it. Only associate the result with this candidate if its source tree matches X or the recorded candidate digest. A passing entire suite at a different SHA is stale. If the candidate has unsaved changes and no corresponding commit, show the SHA check as historical context. Two requirements may share one test; counting edges must never imply two independent tests.

Move SARIF parsing out of `extension.ts` into a pure adapter. Decode location URIs once, resolve artifact index and base IDs, retain tool/rule/fingerprint and the reported source region. Explicitly convert SARIF and patch coordinates into one documented internal convention before intersection. Distinguish old-side deleted lines from new-side added lines. An omitted region yields a file association only; multiple overlapping hunks yield multiple candidate associations. Preserve absent end lines and tool column semantics, including Unicode. Render evidence with source, location, revision, match quality and reviewer disposition. Show obsolete evidence after a proposal changes.

### F. BYOK provider boundaries and polling

Define an adapter with `listConnections` in host-owned storage, `probe(connection)`, `sync(connection, cursor, signal)` and a typed result containing external records, next cursor and warnings. * **Jenkins.** Probe API access with token credentials. Discover nested job paths from returned URLs, encode path segments, validate the origin, and request bounded fields from build APIs. * **BuildKit.** First import an existing OCI image index/provenance or SBOM artifact without running Docker. Resolve the selected platform manifest, its subject digest and associated statements. * **CodeRabbit-style reviews.** Fetch reviews and inline review comments through the GitHub adapter. Associate repository host, numeric IDs, PR number, commit IDs, diff side and ranges. Handle renamed files and outdated comments. Show CodeRabbit attribution only when the returned identity supports it. A direct vendor API is a separate adapter contingent on documented access.
* **All three.** On 401 pause and prompt for replacement credentials. On 403 distinguish insufficient permission from documented rate limiting. Honor retry deadlines on 429. Retry transient reads within a bounded budget, retain the last good view on 5xx, and show its age. Never promote a partial page to a complete sync. ### Release and rollback decisions

If an eligibility gate fails, hold the competition artifact even if all unit suites pass. If a provider integration fails independently, keep its last-good records and disable only its refresh capability. If a schema migration fails, use the intact original for read-only access; avoid opening upgraded storage with an older writer. If concurrent authority or locking is unresolved, ship the registry and isolated read paths with serialized mutations. If a packaged-host test passes once and fails after restart, preserve both logs, reproduce with separate normal and extension-test profiles, and report the precise scope of each result. The final release record should let a second engineer rebuild the same commit, run the same inputs and independently determine which claims the evidence supports.
